# 宇树 R1 连接与远程控制指南

本文档整理了通过网线连接宇树 R1、使用 MobaXterm 远程命令行登录、以及使用 NoMachine 进行图形界面控制的基本流程。示例以 Windows 电脑直连机器人为主。


## 1. 连接前准备

需要准备：

- 一台 Windows 电脑
- 一根网线
- MobaXterm
- NoMachine
- 宇树 R1 机器人已开机并进入正常工作状态

推荐先使用有线连接完成调试。确认 SSH 和 NoMachine 都能正常连接后，再考虑无线联网。

## 2. 网线直连机器人

将电脑和机器人通过网线连接。机器人常见开发网段为：

```text
192.168.123.0/24
```

机器人常用地址：

```text
192.168.123.164
```

电脑需要设置一个同网段、但不与机器人冲突的静态 IP，例如：

```text
192.168.123.200
```

子网掩码：

```text
255.255.255.0
```

## 3. Windows 设置静态 IP

以管理员身份打开 PowerShell 或命令提示符，先查看网卡名称：

```powershell
netsh interface ipv4 show interfaces
```

如果有线网卡名称是“以太网”，设置静态 IP：

```powershell
netsh interface ipv4 set address name="以太网" static 192.168.123.200 255.255.255.0
```

如果电脑显示的是 `Ethernet`、`以太网 2` 或其他名称，需要把命令里的 `"以太网"` 替换成实际网卡名称。

设置完成后检查：

```powershell
ipconfig
```

确认有线网卡 IPv4 地址类似：

```text
192.168.123.200
```

## 4. 测试是否连通

在 Windows PowerShell 或 CMD 中执行：

```powershell
ping 192.168.123.164
```

如果能收到回复，说明电脑和机器人已经网络连通。

如果提示“对象已存在”，通常表示网卡上已经存在 IPv4 配置。可以先检查当前配置：

```powershell
ipconfig
```

如果已经是 `192.168.123.xxx` 网段，可以直接继续 ping。也可以先恢复 DHCP，再重新设置：

```powershell
netsh interface ipv4 set address name="以太网" source=dhcp
netsh interface ipv4 set address name="以太网" static 192.168.123.200 255.255.255.0
```

## 5. 使用 MobaXterm 连接 SSH

打开 MobaXterm，新建 SSH Session：

```text
Remote host: 192.168.123.164
Username: unitree
Port: 22
```

连接后输入机器人对应密码。成功后，终端会显示类似：

```bash
unitree@ubuntu:~$
```

这表示已经进入机器人系统。

MobaXterm 左侧是 SFTP 文件管理器，可以在电脑和机器人之间上传、下载文件：

- 蓝色向下箭头：从机器人下载到电脑
- 绿色向上箭头：从电脑上传到机器人
- 也可以直接拖拽文件到左侧目录

## 6. ROS 版本选择

打开终端时，系统可能提示：

```text
ros:foxy(1) noetic(2) ?
```

一般建议输入：

```text
1
```

也就是选择 ROS2 Foxy。选择完成后会进入正常终端。

可以用下面命令确认：

```bash
echo $ROS_DISTRO
```

如果输出：

```text
foxy
```

说明当前终端已进入 ROS2 Foxy 环境。

只有在教程或工程明确要求 ROS1，例如使用 `roscore`、`rostopic`、`roslaunch` 时，才选择 `2`，也就是 Noetic。

## 7. 使用 NoMachine 进行图形界面控制

确认网线连接和 ping 都正常后，打开 NoMachine，新建连接：

```text
Host: 192.168.123.164
Protocol: NX
Username: unitree
```

输入机器人对应密码后即可进入 Ubuntu 图形桌面。

进入桌面后，可以：

- 打开 Terminal
- 查看文件
- 使用图形界面设置
- 与 MobaXterm 同时保持连接

建议调试期间不要断开网线，避免 SSH 或 NoMachine 会话中断。

## 8. 图形界面中的网络菜单

右上角系统菜单可能只显示：

```text
PCI Ethernet Connected
```

这表示当前系统识别到了有线网卡。

如果菜单里没有 Wi-Fi 选项，可以在机器人终端执行：

```bash
nmcli device status
```

如果输出里只有类似：

```text
eth10   ethernet   connected
eth0    ethernet   unavailable
docker0 bridge     connected
```

而没有 `wifi`、`wlan0` 或 `wlp...`，说明系统当前没有识别到无线网卡。这种情况下不是 Wi-Fi 密码问题，而是无线设备没有被系统识别或没有启用。

可以进一步检查：

```bash
rfkill list
lsusb
lspci | grep -i -E "wireless|wifi|network"
```

在没有确认无线可用前，不建议拔掉网线。

## 9. 常见问题排查

### ping 不通

优先检查：

- 网线是否插好，网口灯是否亮
- 机器人是否完全开机
- 电脑有线网卡是否设置为 `192.168.123.xxx`
- 子网掩码是否为 `255.255.255.0`
- 是否设置到了错误的网卡，例如 Wi-Fi 或虚拟网卡
- 是否有 VPN、虚拟网卡影响路由

可执行：

```powershell
ipconfig
arp -a
ping 192.168.123.164
```

### MobaXterm 能连但 NoMachine 连不上

检查：

- NoMachine 地址是否为 `192.168.123.164`
- 协议是否为 NX
- 用户名是否为 `unitree`
- 机器人 NoMachine 服务是否正在运行
- 电脑和机器人是否仍然在同一网段

### 终端一直询问 ROS 版本

这是正常现象。输入 `1` 选择 Foxy 后即可继续。

### 不要轻易执行系统升级

调试阶段不建议执行：

```bash
sudo apt upgrade
sudo apt autoremove
sudo reboot
```

系统升级可能影响机器人预装环境。重启也可能中断当前远程连接。

## 10. 推荐连接顺序

推荐按以下顺序操作：

```text
1. 网线连接电脑和机器人
2. Windows 设置静态 IP：192.168.123.200
3. ping 192.168.123.164
4. MobaXterm SSH 登录机器人
5. 终端选择 ROS2 Foxy，也就是输入 1
6. NoMachine 连接 192.168.123.164
7. 保持网线连接，进行后续调试
```

只要 `ping 192.168.123.164` 能通，并且 MobaXterm 显示 `unitree@ubuntu:~$`，就说明命令行远程连接已经成功。NoMachine 能进入 Ubuntu 桌面，则说明图形界面远程控制也已经成功。
